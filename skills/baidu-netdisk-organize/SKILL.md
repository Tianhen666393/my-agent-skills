# 百度网盘整理

## 触发词：「接入网盘」

仅在用户明确用 **「接入网盘」** 要求执行时，进入接入流程，不要先做整理。只是讨论、引用、转述或顺带提到这四个字时，不执行自检、授权或其他操作。
**只认这四个字**，不要自作主张扩展成别的说法。

**第一步：只读自检，不问他任何事**

```bash
python scripts/bdpan.py whoami
```

- **通了**：告诉他"当前 token 还有效，账号是 XXX，可以直接开工，不需要重新接入"。除非他明确说要重来，否则到此结束。
- **不通**（报缺 token、`errno=110`、`-6` 等）：进入第二步。

**第二步：先确认，再动手**

问他一句：**"确认现在重新接入百度网盘吗？"** 等明确回复。

在他说确认之前：**不引导授权、不写任何 token 文件、不做任何写操作。** 只有这一步的只读自检可以直接跑。

**第三步：确认后，给步骤 + 干活**

1. 把 `references/接入与续期.md` 的《首次接入》原样给他：授权链接、勾选项、去哪找 token。
2. 说明他的动作：打开链接 → 登录 → 勾「在您的百度网盘创建文件夹并读写数据」→ 授权 → **去地址栏**复制 `access_token=` 后面那一串。
3. 说明我的动作：拿到 token 后我会验证，并告诉他结果。
4. 拿到 token 后执行验证：

   ```bash
   python scripts/bdpan.py whoami
   python scripts/bdpan.py ls --dir "/"
   ```

   把**账号名**和**根目录条目数**报给他。
5. 建议他把 token 存进文件，这样以后新聊天不用再发：

   ```powershell
   Set-Content -LiteralPath "$env:USERPROFILE\.codex\baidu_netdisk_token.txt" -Value "<token>" -NoNewline -Encoding UTF8
   ```

   这一步由他自己执行；除非他明确要求，不要代替他把 token 落盘。
6. 全部通过后回一句「接入完成」，并告诉他之后可以直接说"整理网盘"开工。

官方换了体验密钥、授权链接打不开时，按 `references/接入与续期.md` 里《官方把体验通道的密钥改掉了怎么办》走，去官方 MCP 仓库 README 取新链接。

## 开场必须先跟用户确认两件事

范围和落点**每次都要问，不许自己定**：

1. **这次整理哪个文件夹**（要绝对路径），含不含子目录。
2. **`Agent整理` 建在哪一层**：
   - 网盘顶层 `/Agent整理/`——适合一次整理多个顶层文件夹或做全盘整理；
   - 被整理文件夹内部，例如 `/来自：V2339A-待处理/Agent整理/`——适合只清一个文件夹，产物和来源放在一起。

用户这次已经讲清楚了可以跳过；**落点没说明时必须问**。

## 落点确定后，先检查残留

```bash
python scripts/bdpan.py agent-check --root "<确定的路径>"
```

- `RESULT=missing` → 建好标准子目录，继续。
- `RESULT=clean` → 继续。
- `RESULT=blocked` → 里面还有用户没清理的文件。**立刻停止本次整理**，按子目录列出来提醒用户，等他明确说清理完了再动手；期间不移动、不新建、不覆盖。

## 先勘察，再定方案（不许跳过）

**每个顶层文件夹里的东西都不一样，不能上来就套下面那套桶。**

确认范围和落点之后，紧接着做**勘察**：

```bash
python scripts/bdpan.py walk --dir "<目标文件夹>" --out work/survey.csv
```

统计四件事，报给用户：

> ⚠ **统计前必须按 `path` 去重**：百度接口会把同一条目重复列出 2～4 次（实测 159,502 条里只有 125,518 个不同路径）。不去重会把文件数、体积和重复量统统算大——实测把 5.62 GB 的重复算成了 48.63 GB。

| 看什么 | 怎么看 |
| --- | --- |
| 文件类型分布 | 按扩展名、按 `category` 字段分组计数 |
| 目录结构 | 一级/二级子目录有哪些、有没有很深的嵌套、有没有空目录 |
| 体量 | 文件总数、总体积、最大的几个文件是什么 |
| 特殊内容 | 代码、安装包、数据库、工程文件（.psd/.ai/.prproj/.sch/.pcb/.step）、字体、镜像、压缩包、种子…… |

**勘察完先出整理方案，等用户拍板再动手。** 方案里必须写清三件事：

1. 建议分几类、每类叫什么、按什么判据分（扩展名 / 内容识别 / 来源目录）；
2. 哪些能自动判，哪些判不了——判不了的去 `其他` 还是用户指定的兜底目录；
3. **勘察出来但现有规则覆盖不到的类型，必须提出来让用户定**，不要自己发明分类。

下面那套桶**只是"图片 + 视频 + 文档为主"时的默认值**。如果勘察发现这个文件夹里主要是别的东西（一整包代码、一堆工程文件、大量数据库备份……），就先按上面的流程问清楚再定新桶，不要因为已有默认值就硬套。

## 默认桶（仅当勘察结果适用时）

按**文件类型**分流，不做题材判断：

| 路径 | 放什么 | 怎么判 |
| --- | --- | --- |
| `<Agent整理>/文档/` | 所有文档，含 PDF 和电子书，**不再细分** | 扩展名（.doc/.docx/.pdf/.xls/.xlsx/.ppt/.pptx/.txt/.md/.epub/.mobi/.azw3/.azw…）＋ CLIP |
| `<Agent整理>/音频/` | 所有音频 | 扩展名 .mp3/.m4a/.flac/.wav/.aac/.ogg |
| `<Agent整理>/视频/` | 所有视频 | 扩展名 .mp4/.mov/.mkv/.avi/.wmv/.flv/.m4v/.3gp |
| `<Agent整理>/截图/` | 屏幕截图：游戏画面、应用界面、聊天、网页、长截图 | 文件名（`Screenshot_`、截屏、屏幕截图）＋ 屏幕比例 ＋ CLIP |
| `<Agent整理>/拍照/` | 相机或手机实拍照片 | 来源路径（`DCIM/Camera`）＋ 文件名（`IMG_`）＋ CLIP |
| `<Agent整理>/隐私敏感/` | 身份证、户口、银行卡、订单、含姓名学号的单据、医疗影像 | 本机 OCR 关键词 ＋ CLIP（证件 / 单据） |
| `<Agent整理>/其他/` | **除截图、拍照、隐私敏感以外的一切图片**，以及类型不明、代码、压缩包等 | 兜底 |
| `<Agent整理>/清单/` | CSV 清单与统计 | — |

**图片只有三个去处：`隐私敏感`、`拍照`、`截图`；三个都不满足的一律进 `其他`。**

几条重要约定：

- **截图不区分是哪个游戏**。游戏截图一律留在 `截图/`，由用户自己清。这是刻意设计：实测没有可靠办法自动判断游戏归属，硬猜只会制造错放。
- **不设"分类结果"目录**。曾经用 OCR 认作品再单列目录，命中率只有 2.7%，为了这点收益要多维护一个目录不划算；OCR 认出的结果只写进清单 CSV，文件本身仍按类型入桶。
- **文档不再细分**：PDF、EPUB、MOBI 一律进 `文档/`。用户明确说过不区分书籍，因为 PDF 里既有书也有手册和课件，细分只会增加负担。
- 判不准一律进 `其他`，不要硬猜。
- 代码、压缩包目前没有定规，进 `其他`，遇到再跟用户讨论。

## 隐私红线

- 相机照片、`隐私敏感/` 下的内容，以及任何被判定为隐私的文件，**绝不允许上传到任何联网服务**——以图搜图、云 OCR、云端大模型都不行。
- 顺序不可颠倒：**先在本地做完隐私筛查，再对剩下的联网处理**。禁止先上传再筛选。
- 判定尽量在本地做：本地 OCR 关键词、本地 CLIP 分类、路径与文件名规则。

隐私关键词表（本机 OCR 命中即进 `隐私敏感`，可按需扩充）：

```
身份证 户口 银行卡 卡号 学号 成绩单 录取通知 准考证 学生证
驾照 护照 医保 社保 订单编号 发票 收据 合同 聘书 证书
```

地址类（本机实测有效）：`怀化学院`、`靖州`、`渠阳镇`、`苗族侗族` 这类地名。

## 工作流

1. 确认范围和落点。
2. 检查残留，必要时停下等用户。
3. **勘察目标文件夹**：统计类型分布、目录结构、体量、特殊内容。
4. **出整理方案给用户确认**：分几类、每类判据、哪些判不了、有没有规则覆盖不到的类型。
5. 用户确认后，**按目录**逐个递归列出候选文件，不要一次性扫全盘。
6. 按扩展名和来源路径做第一层分流。
7. 取缩略图，在本地跑隐私筛查（CLIP ＋ OCR）。
8. 剩下的图片按 `隐私敏感` / `拍照` / `截图` 分流，三个都不满足的一律进 `其他`。
9. 生成 CSV 清单（原路径 → 归类 → 判定依据），**先给用户看，确认后再移动**。
10. 用服务端 move **逐个**移动（`--per-file`），不下载也不上传；只移动不删除，留操作日志。
11. 收尾：重新扫一遍源目录核对，报告结果，清掉本地缓存。

用户只说"先给清单"时，不要顺手移动文件。

## 结论的有效性与复验

`references/bdpan-api.md` 里的接口行为是**某个时点实测的结果**。百度网盘是外部服务，行为随时可能变，**不要把任何一条当成永久事实**：

- 动手前用最小成本复验关键假设，命令见参考文件里的《动手前复验》。
- 复验通过：按记录的做法做。
- 复验失败或出现新现象：改用当时有效的做法，并把「日期 + 现象 + 新结论」追加到参考文件的《变更记录》，旧结论**保留并标注失效时间**。
- 新结论必须写明实测日期和测试条件，并区分"稳定复现"和"只见到一次"。

## 什么算做得好

- 每个文件都落到一个桶里，类型判断没有硬猜的成分。
- 隐私内容一份都没外传，且都能在 `隐私敏感/` 或 `拍照/` 里找到。
- 用户需要动手的只有 `截图/`、`拍照/` 和 `其他/`，其余桶他基本不用碰。
