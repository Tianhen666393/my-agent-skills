# （已停用）按作品 / 题材维度的分类方案

**状态：2026-10-05 停用，不要执行。** 保留备查，以后技术条件变了（出现可靠的作品识别模型、或用户愿意付费买图片检索额度）可以重新启用。

## 停用原因

实测三条路都不成立：

1. 本地 CLIP 认不出具体作品。用作品名做零样本提示，与 OCR 已知答案只有 **8%** 一致；把同款游戏和不同款游戏分开的余弦差距只有 0.13（同 0.60 / 异 0.47），做不到可靠聚类。
2. 开源生态里没有可用的作品分类模型。WD 系列标注模型（SmilingWolf）与 DeepDanbooru 的标签表只有"通用词 + 角色名"，没有作品标签；deepghs 的 `anime_classification` 只分 3D / 动画 / 漫画 / 插画四类。
3. 在线以图搜图不可批量。SauceNAO 的 API 明确拒绝匿名调用（`The anonymous account type does not permit API usage.`），要 API key，免费额度按天算，五千多张要跑几十天。

结论：只能靠人工认作品，成本不划算。改为按文件类型分流（见 SKILL.md）。

```
<Agent整理>/分类结果/<分类名>/  已识别出归属的文件
<Agent整理>/清单/
```

## 当时的分类规则

1. **内容类型优先于作品**：跨作品的通用类型做一级目录，不塞进作品目录。
2. **单一作品图片少于 10 张就不单独建目录**，并入 `好看的-虚拟`。
3. 「有意思的东西」「好看的」这类主观分类，agent 判不准就进 `不确定`。
4. 发票、收据、证书可以靠本地 OCR 识别，不要无脑扔兜底。

## 当时的通用内容类型目录

抽卡记录、练度、建模、风景、好看的-虚拟、好看的-真实

- 练度是合并类型，包含：强化、原神极中极（圣遗物词条完美）、圣遗物/遗器相关内容。
- `好看的-虚拟`、`好看的-真实` 同时承担小体量作品的兜底。

## 当时不自动分类、一律进 `不确定` 的类型

`表情包`、`弔图`、`画师`、`绘画练习`、`有意思的东西`。

原因：表情包与弔图的界线是用户自己划的；画师属于作者归属而非画面类型；绘画练习分不清练习与成品。

## 当时各类别的可判断程度

| 目录 | 程度 | 判断依据 |
| --- | --- | --- |
| 视频 / 音频 / 文档 | 能 | 扩展名与 category 字段 |
| 相机照片 | 能 | 来源路径（DCIM/Camera、IMG_ 前缀） |
| 发票 | 能 | 本机 OCR 读到"发票""增值税""发票代码""税号" |
| 证书 | 能 | 本机 OCR 读到"证书""荣誉""聘书""奖状" |
| 重要文件 | 能 | 合同、协议、正式通知 |
| 抽卡记录 | 能 | 卡池界面、十连结果、稀有度光效、"概率"等 UI 文字 |
| 建模 | 能 | 3D 软件界面（Blender / Maya / 3ds Max / Substance）、UV 展开图、线框图 |
| 风景 | 半 | 无明显主体的自然或城市景观 |
| 练度 | 半 | 角色面板、属性词条页面 |
| 表情包 / 弔图 / 画师 / 绘画练习 / 有意思的东西 | 不分 | 一律进 `不确定` |

## 这次实测留下的有用数据
