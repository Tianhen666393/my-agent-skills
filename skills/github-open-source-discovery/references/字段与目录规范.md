# 目录、字段与复核规范

来源：原项目级 `AGENTS.md` 第 2 节，2026-10 迁移为 skill。字段与命名必须与 `项目总目录.xlsx` 的「说明」工作表保持一致。

## 目录结构

```text
docs/github-projects/
├── 项目总目录.xlsx          # 生成物，禁止手工编辑
├── 待观察项目.md            # 权威源
├── 项目详情/
│   ├── YYYY-MM-DD_项目详情.md
│   └── YYYY-MM-DD_项目详情_02.md   # 同一天条目超过 25 条时新建
├── tools/build_catalog.py   # 重建表格的脚本
└── 归档/                    # 迁移归档的旧文档
```

## 序号与详情条目

- 序号全局唯一，格式 `P0001`，按发现日期递增，作废也不复用。
- 详情按日期拆分，不同日期不得混放；文档头部写明覆盖日期、序号范围和条目数。
- 条目标题为 `### P0001 项目名称`。
- 条目字段固定，格式必须是 `- **字段名**：值`（脚本据此生成表格）：仓库链接、发现日期、类别、标签、项目状态、是否电赛相关、核验状态、热度、热度备注、目录备注、复核优先级、上次复核日期、复核次数、主要功能或技术亮点、主要技术栈或核心芯片、开源内容、推荐理由、学习或复现基础、可复用内容、风险/缺口或待核验事项、再次推荐条件、后续跟踪建议。
- 类别只能取词表中的一个值：仪器仪表、射频与无线、嵌入式与数字系统、开发板与开源硬件、通信与信号处理、工具链与软件框架、竞赛与资料、AI 与智能体、开发工具与效率、系统与基础设施。新增类别必须同步更新表格「说明」工作表与本文件。
- 标签写具体的芯片、平台、接口、形态等属性，逗号分隔，且不重复类别词。
- 热度字段格式固定为 `stars=数字；forks=数字；查询日=YYYY-MM-DD`。
- 目录只存热度快照与一句话简介，完整介绍一律留在详情文档。
- 表格样式（表头居中、冻结首行与首列、按列对齐、按内容自适应列宽）由脚本统一生成，不得手工调整。

## 复核机制

- 跟随寻宝流程执行，先复核后检索，每轮上限 5 个项目。
- 复核优先级取第一个匹配项，停更或归档项目一律为 6：

| 优先级 | 对象 | 间隔（天） |
| :--- | :--- | :--- |
| 1 | 待观察表中已到期的项目 | 30 |
| 2 | 被标记为重点学习对象的项目 | 45 |
| 3 | 状态为新项目或早期的项目 | 60 |
| 4 | 状态为活跃的项目 | 90 |
| 5 | 其余项目（含部分核验、待核验） | 90 |
| 6 | 状态为停更或归档的项目 | 180 |

- 是否到期由表格公式按「上次复核日期 + 复核间隔」计算，禁止填写或预测「下次复核日期」。
- 复核检查项：stars 与 forks 变化、最近推送时间与是否归档、最新 release 版本与日期、许可证变化、状态是否需要改判、是否出现重大更新。
- 复核结果：原地更新目录行（复核次数加一、上次复核日期改为本次日期），并在详情条目下追加 `#### 复核记录`，只追加、不改旧文案。
- 达到再次推荐条件时，在本轮检索结果中复述该项目并说明原因。
- 复核发现项目已归档或 404 时，不删除目录行，状态改为「已归档 / 不可访问」并写明复核日期。
