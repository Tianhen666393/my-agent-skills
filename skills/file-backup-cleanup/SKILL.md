# 文件管理、备份与删除规范 (File Backup & Cleanup Policy)

## 1. 核心原则：以“移入同盘日期回收站”替代“硬删除”
- **默认动作与自动建目录**：所有需要删除的文件或目录（下述 2.A 级临时产物除外），一律移动至**源文件所在盘符**的 `<盘符>:\.agent_trash\YYYY-MM-DD\`（本机为 C、D、T 盘）。若该盘符下尚无 `.agent_trash` 根目录或当天日期子目录，Agent 无需询问用户，直接自行创建完整多级目录（如使用 `New-Item -ItemType Directory -Force` 或 `mkdir -p`，已存在则沿用）；**严禁跨盘移动到其他盘符**。
- **同日重名防碰撞闭环（检测 + 原子递增重试）**：向回收站移动同名文件/目录前，必须先执行目标路径占用检测。若当天已存在同名项，目标名称追加 `原名称.HHMMSS_fff_bak`；若仍冲突或遇到并发占用，使用递增序号 `_01_bak`、`_02_bak` 循环重试；移动时严禁使用强行覆盖参数（如禁止 `-Force` / `/Y` 覆盖同名目标），确保原子安全写入，绝对不覆盖既有文件。
- **目录与软链接安全检查**：
  - **C 级文件向上传染原则**：移动任何非 2.A 级目录前，须先递归检查其内部是否包含 2.C 级受保护文件（或 `.git/`）。只要目录内含任一 2.C 级文件，整目录一律自动升级按 **2.C 级** 流程申请确认；含 `.git/` 则严禁移走。
  - **符号链接与联接点（Symlink / Junction）**：清理或移动符号链接、目录联接点（Junction）或硬链接时，**仅允许解除链接本身**或将链接本体移入回收站，严禁穿透（Follow）链接去修改、移动或删除其指向的目标源目录/源文件。
- **严禁清空**：严禁执行任何清空任一盘符下 `.agent_trash\` 及其子目录的命令；各盘符回收站的彻底销毁与清理权限仅归属人类用户。

## 2. 删除与归档分级授权流程

### A. 允许直接物理删除（免确认，仅限会话临时产物与缓存）
- **适用范围**：当前会话中由 Agent 自行生成且确认不再需要的临时脚本或调试输出（如 `test_temp.py`、`debug_output.json`），以及通用构建产物与缓存目录（如 `dist/`、`build/`、`.cache/`、`__pycache__/`、`node_modules/.cache/`）。
- **边界约束**：仅允许删除缓存目录本身，严禁删除依赖配置文件及 lock 文件。

### B. 直接移动到当天回收站（免确认归档，豁免全局批量/跨目录确认）
- **适用范围**：编译中间产物、已被新文件完整替代的非核心测试文件、用户明确要求清理但无需永久粉碎的普通文件、符合过期归档条件的旧备份副本。
- **执行方式**：免确认直接（支持单文件或批量）移入源盘 `<盘符>:\.agent_trash\YYYY-MM-DD\`，不受全局“跨目录/批量操作须确认”限制，在任务结束时汇报归档路径即可。

### C. 必须先获得用户显式确认后移入回收站
- **适用范围**：源代码文件、业务数据、数据库文件（如 `.sqlite`、`.db`）、环境变量与配置文件（如 `.env*`、`config.yaml`、`settings.json`）、包管理锁文件（如 `package-lock.json`、`pnpm-lock.yaml`、`Cargo.lock`、`poetry.lock`）、版本控制相关文件，以及任何内部包含上述文件的目录。
- **绝对禁区**：`.git/` 目录严禁任何形式的删除或移走。
- **强制确认模板**：执行 C 级文件/目录移走前，必须向用户列明以下四项并暂停等待回复：
  1. **明确目标**：即将移走的完整源文件路径（若为目录须注明内部包含的 C 级文件），不得使用通配符或笼统表述。
  2. **说明原因**：为何该文件/目录冗余或需要移除。
  3. **目标流向**：将被移至源文件所在盘符的回收站日期目录，如 `D:\.agent_trash\YYYY-MM-DD\`。
  4. **等待回复**：在用户明确输入**“确认 / 同意 / yes”**前，不得执行移动操作。

## 3. 严格禁止的危险命令模式
任何情况下，Agent 均不得生成或执行以下指令：
- 除清理 2.A 明确列出的临时缓存目录外，严禁执行不可逆物理删除指令，包括 `Remove-Item -Recurse -Force`、`del /f`、`rmdir /s /q`、`rm -rf`。
- 严禁带通配符的危险删除，如 `rm -rf *`、`del /s /q *.*`、`Remove-Item -Recurse *`。
- 严禁在磁盘根目录、用户家目录（`C:\Users\<User>\`）或系统目录（`C:\Windows\`）下执行无特定目标的清理命令。
- 严禁任何试图绕过用户权限或绕过本规范的隐式删除操作（如通过编写临时脚本偷偷调用系统删除 API 销毁 B/C 级文件）。

## 4. Agent 工作备份集中管理
- **统一位置与自动建目录**：所有 Agent 在工作中主动生成的备份，统一存入源文件所在盘符的 `<盘符>:\.agent_backups\YYYY-MM-DD\任务名称\`（C、D、T 盘各自使用本盘目录）。若该盘符下尚无 `.agent_backups` 根目录、当天日期目录或任务子目录，Agent 无需询问，直接自行创建完整多级目录（已存在则沿用）。严禁跨盘备份；不得散放于项目目录、文档目录或临时目录。用户另有明确指定时遵从用户指定；软件自身管理的备份不擅自搬动。
- **用途区分**：`.agent_backups` 保存供恢复使用的副本，原文件继续保留；`.agent_trash` 接收移除或过期的文件。测试产物不是正式备份，任务结束时按第 2 节清理，不混入备份目录。
- **命名与防覆盖闭环**：任务名称应清晰说明备份对象；同日多次备份必须先做目标存在性检测，通过追加毫秒级时间戳、随机后缀或递增序号区分，严禁覆盖既有备份。不同源路径的同名文件须在备份目录内以独立子路径区分清楚。
- **中文备份说明**：每个备份目录必须创建中文撰写的 `备份说明.md`，记录以下 7 项内容：
  1. 原文件完整路径
  2. 备份文件或目录对应关系
  3. 备份时间
  4. 执行 Agent
  5. 备份原因
  6. 恢复方法
  7. 适用的保留期限
  *(安全注意：说明文档中严禁记录明文凭据、密钥或敏感环境变量值。)*
- **过期归档**：保留期限以用户明确授权为准，不对所有备份擅自套用统一期限。AI 工具台账备份在下次成功登记后，将备份时间超过 30 天的副本及说明移入同盘 `.agent_trash\当天日期\`；此类过期副本按 2.B 处理（免逐次确认，不得移动原文件，也不清空回收站）。过期判定一律按**备份生成时间**计算，不能用原文件修改时间代替。
- **旧备份迁移与报告**：既有散落备份不自动迁移，须先列明完整路径及目标流向并获得用户确认。任务结束时须报告新增备份和归档的具体位置，避免留下无法识别的副本。
